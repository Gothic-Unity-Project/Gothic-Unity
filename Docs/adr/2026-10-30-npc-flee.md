# ADR: NPCs flee

- Status: proposed
- Date: 2026-10-30

## Context

Cowards, beaten NPCs and weak animals run away in Gothic: their scripts start the flee state, which tells them again and again to flee from their enemy. That instruction did nothing here, so fleeing NPCs stood still in front of the hero.

## Decisions

1. **Fleeing runs along the way network, like the engine.** Each step heads for the waypoint within 5 meters that the NPC can see and that is farthest from the enemy. The script's flee state repeats the step until the NPC is far enough. Not chosen: a navigation mesh, which the game doesn't have yet and the engine doesn't use for this.
2. **Without such a waypoint the NPC runs straight away from the enemy,** also when the best one nearby is closer to the enemy than the NPC itself. A wall right ahead turns that escape sideways, to the free direction closest to straight away.
3. **A fleeing NPC runs like any running NPC,** with the run animation and the running body state the scripts can check. The run goes on from one step to the next without a stop in between. In Gothic 1 the flee state waits a second after each step; the NPC keeps running through that wait, like in the engine.
4. **The run stops, back to standing, when the flight ends:** no further flee step follows, the scripts clear the NPC's queue, or its state changes. Death and knockout take over the body themselves.
5. **Walls are what the NPC's line of sight treats as walls: the world and fixed objects.** Not chosen: counting doors and other NPCs, which none of the NPC's other checks do either.

## Consequences

- Cowards and beaten NPCs run away from the hero along paths instead of freezing.
- Away from waypoints, in tight places, a fleeing NPC can still get stuck in a corner.
- Unlike the engine, waypoints under water are not skipped yet.
